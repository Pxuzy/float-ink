# 悬浮画笔（float-ink）开发目标

## 总目标

把 `v0.3.0` 维护成一个真实可用、低干扰、可回退的 Android 悬浮讲解笔：用户能够在手机或平板上稳定打开透明画板，用手指或手写笔进行标注，快速切换绘图工具和颜色，完成讲解后退出并回到原 App。

## 当前阶段目标

当前阶段不是继续堆叠新功能，而是完成 `v0.3.0` 的真实可用性收口：

1. 证明核心流程在真实 Android 手机和平板上可用。
2. 修复真机发现的崩溃、触摸穿透、服务退出、遮挡、旋转和窄屏问题。
3. 统一文档、测试和版本事实，避免把历史分支能力误认为当前主线能力。
4. 在真机基线稳定后，再实现最终确认的颜色管理方案。

## 核心用户目标

用户应该能够：

- 授予悬浮窗权限并启动悬浮球
- 将悬浮球拖到屏幕内任意位置；需要时靠近边缘并自动隐藏到边界
- 点击悬浮球立即进入透明画板
- 用手指或手写笔绘制
- 在画笔、直线、箭头、矩形和圆形之间切换
- 修改颜色、线宽和箭头比例
- 撤销或清空当前图层
- 在多个画板和图层之间切换
- 独立黄金参考线辅助构图，支持水平与垂直方向
- 独立斐波那契回撤工具辅助讲解比例关系，支持两点绘制和多档水平等级线
- 隐藏、显示和排序图层
- 点击退出后清除本次临时笔迹并恢复底层 App

## 产品边界

必须保持：

- Android 原生实现
- Android 29+ 手机和平板
- 绘制层接管触摸，退出后恢复底层触摸
- 不截图、不录屏、不读取底层 App 内容
- 不上传笔迹、不做云同步
- 不引入 AccessibilityService 或 MediaProjection
- 不在服务器上安装与当前任务无关的大型工具
- 设备更新只通过经过签名的 APK Release 完成

## 后续颜色目标

最终颜色交互采用清晰的职责分离：

### App 画笔页

负责低频颜色资产管理：

- 查看内置色和自定义色
- 新建自定义色
- 编辑颜色
- 删除自定义色并二次确认
- 默认色不可删除
- 删除当前使用的颜色时安全回退
- 更新全局和各工具样式引用
- 将修改实时同步到正在运行的画板

### 悬浮栏

只负责高频选色：

- 显示当前颜色
- 显示内置色和最近使用颜色
- 点击后立即切换下一笔颜色
- 不显示添加、删除、管理、RGB 或调色器入口
- 保持窄屏下的可见性和至少 48dp 触控区域

RGB-only、HSV 或其他精确编辑方式必须在实现前单独确认，不得把历史分支的多个方案混合进主线。

## 验收标准

### 自动化验收

- `./gradlew testDebugUnitTest` 通过
- `./gradlew :app:assembleDebug` 通过
- `git diff --check` 无输出
- APK 包名为 `com.pxuzy.floatingpen`
- APK 版本与当前 Git 标签一致
- 不产生未跟踪的密钥、Token、本机配置或构建产物提交

### 真机验收

至少覆盖：

- 一台 Android 手机
- 一台 Android 平板
- 竖屏和横屏
- 普通窗口和分屏窗口
- 手指和手写笔
- 权限拒绝后重新授权
- 服务停止后重新启动
- 悬浮球中央自由停留、靠边隐藏开关、左右边缘延迟隐藏、唤醒和旋转恢复
- 画板/图层切换、显隐、排序和删除
- 颜色、线宽、形状和撤销/清空
- 退出后底层 App 恢复触摸

真机未覆盖的项目必须明确标记为“未验证”，不能使用“已完成”或“兼容”表述。

## 开发顺序

1. 真机安装并执行 `v0.3.0` 核心流程验收。
2. 修复 P0/P1 真机问题，每个修复单独测试和提交。
3. 更新真机验收矩阵和项目状态文档。
4. 确认颜色管理交互方案。
5. 实现颜色管理的最小完整切片：数据边界、App 管理、悬浮栏选色、运行中刷新和回归测试。
6. 再次执行完整测试、构建和真机验收。
7. 确认后才决定版本升级、远端主线同步和正式发布。
