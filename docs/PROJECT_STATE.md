## 项目定位

悬浮画笔（FloatPen）是一个轻量、低干扰的 Android 悬浮屏幕讲解笔，面向手机和平板上的讲课、演示和远程指导场景。

核心流程：

```text
可拖动悬浮球
  → 点击进入透明全屏画板
  → 手指或手写笔绘制标注
  → 使用工具、颜色和撤销/清空操作
  → 点击退出
  → 清除本次临时笔迹并返回原 App
```

它不是截图编辑器，也不是云端白板产品。

## 当前产品边界

### 已确认

- 首发平台：Android 手机和平板
- 支持范围：Android 29+
- 技术栈：原生 Android / Kotlin / Gradle
- 绘制层出现时接管触摸，底层 App 不应响应绘图操作
- 退出绘图层后底层 App 恢复触摸
- 当前会话中的笔迹默认是临时的
- 不截图、不读取、不上传底层 App 内容
- 悬浮窗服务使用用户授予的系统权限
- 设备更新通过 GitHub Releases 的 APK 完成，不在设备上执行 `git pull`

### 明确不做

- iOS / iPad
- 截图、录屏、图像导出
- 云同步、登录和统计分析
- AccessibilityService、MediaProjection
- 相机、麦克风和广泛存储权限
- 完全静默的后台安装 APK
- 在没有真实验证的情况下宣称设备兼容

## 开发约束

- 先读 `README.md`、本文件和 `docs/GOAL.md`
- 小步实现，每个阶段独立测试和构建
- 不把自动化测试通过写成真机已验收
- 不恢复已经明确排除的截图、录屏、云同步和 iPad 方向
- 修改后运行 `./gradlew testDebugUnitTest :app:assembleDebug`
- 提交前运行 `git diff --check`
- 提交信息只使用远端仓库的标签格式（英文 type/scope + 中文标题）：

```text
feat(theme): 中文标题

- 具体改动
- 行为影响
- 测试和构建验证结果
```

- `.githooks/commit-msg` 校验标签格式：中文类型（修复/重构/合并/发布…）会被拒绝并给出对应英文，`type` 取远端历史用过的英文集。
- 版本标签沿用 `v<major>.<minor>.<patch>`（与远端一致），不移动远端已有标签。
- `.githooks/pre-push` 只放行快进推送：非快进覆盖远端历史、删除远端引用、移动远端已有标签一律拒绝（`ALLOW_REMOTE_REWRITE=1` 可显式跳过）。本地提交必须先 rebase 到 `origin/main` 之上，只往远端“加”提交。

## 软件端更新钩子

- 软件检查 GitHub Releases 的 `latest` 正式版本，并只接受更高版本号。
- 下载完成后、启动系统安装器前校验 APK 包名、`versionCode` 和悬浮画笔正式签名证书 SHA-256。
- 校验失败不调用安装器，阻止错误包、降级包、未签名包和不同签名包破坏覆盖安装。
- 如果当前已安装版本不是正式签名包，提前提示用户备份数据、卸载旧包后再安装，避免系统安装器最后才报告签名冲突。
- 同一正式签名覆盖更新由 Android 保留应用数据；不同签名无法通过任何钩子绕过系统限制，需使用历史会话导出/导入完成迁移。

## 发布签名门禁

- Release 构建缺少签名环境时直接失败，不再允许生成可发布但未签名的 APK。
- GitHub Release 使用固定的悬浮画笔发布证书 SHA-256 校验，防止新旧版本无法覆盖安装。
