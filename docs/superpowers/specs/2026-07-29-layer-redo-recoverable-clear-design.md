# FloatInk 图层级重做与可恢复清空设计

日期：2026-07-29

分支：`feat/ui-quiet-capsule-rgb-keyboard`

## 目标

补齐当前绘图流程的纠错闭环，同时保持 FloatInk 轻量、低干扰的悬浮体验：

- 撤销最后一个已完成元素后，可以重做恢复；
- 清空当前图层后，可以一次恢复清空前的全部元素；
- 不在 320dp 紧凑工具栏中增加常驻按钮；
- 不改变画板、图层、绘图元素和 `.floatink` 文件格式。

## 参考与取舍

- Saber、Rnote 将撤销和重做作为基础编辑闭环，并为历史行为设置独立测试。
- Excalidraw 与 tldraw 在移动端保持主工具栏紧凑，把上下文操作与绘图工具分层。
- FloatInk 当前在窄屏下固定保留撤销、清空、退出；直接增加常驻重做按钮会压缩工具区。

因此采用“上下文恢复条”，而不是固定双按钮或长按手势。仅参考交互原则，不复制 GPL 或专有许可证项目代码。

## 交互设计

### 撤销

点击撤销时：

1. 如果正在绘制，先取消未完成手势，不修改已完成历史；
2. 否则移除当前图层最后一个元素；
3. 在工具栏附近显示轻量恢复条，主操作为“重做”；
4. 点击“重做”把该元素恢复到原图层末尾。

### 清空

点击清空时：

1. 取消未完成手势；
2. 如果当前图层非空，将全部元素作为一个历史操作移出；
3. 显示恢复条，主操作为“恢复清空”；
4. 点击后一次恢复清空前的全部元素及原顺序。

空图层点击清空不创建历史、不显示恢复条。

### 恢复条

- 使用现有 `toolbar-popup-host`，与颜色、更多工具、画板面板共享安全定位逻辑；
- 显示简短结果文本和一个明确操作按钮，不采用 Toast；
- 不自动超时，直到恢复、关闭、产生新历史分支或服务结束；
- 在紧凑宽度下内容可收缩，不遮挡工具栏和系统导航区域；
- 颜色、更多工具、画板面板与恢复条可以共存时仍不得互相遮挡；若空间不足，恢复条优先贴近工具栏，临时面板继续使用现有安全定位。

## 历史模型

历史按图层 ID 独立保存，仅存在于当前进程会话：

- `undo` 栈保存已经完成、可以撤销的历史操作；
- `redo` 栈保存已撤销、可以恢复的历史操作；
- 单笔添加、整层清空都实现为可逆操作；
- 撤销后开始新笔迹，当前图层的 `redo` 栈立即清空；
- 切换画板或图层不删除其他图层的历史；
- 删除图层或画板时清理其历史，避免持有无效元素；
- 从历史文件替换整个会话、停止服务或清空会话时清空所有运行时历史。

历史不序列化到 `.floatink`。重新打开 App 后只恢复绘图内容，不承诺恢复上次运行的撤销/重做栈。

## 数据流

1. `DrawingOverlayView` 完成元素时，通过 `DrawingSession` 记录“添加元素”操作。
2. 撤销、重做和清空都由 `DrawingSession` 修改当前图层，View 不直接操作 `elements`。
3. 每次成功的撤销、重做、清空或恢复清空都调用 `onSessionChanged()`，触发现有 800ms 防抖自动保存。
4. View 根据当前图层是否可重做刷新恢复条；切换图层后显示该图层自己的可恢复操作。
5. 绘制预览仍由 View 管理，未完成手势不进入历史。

## 边界行为

- 撤销期间点击画布产生新元素：旧重做分支作废；
- 撤销一个清空操作后，可再次重做该清空；
- 连续撤销多笔时，重做按相反顺序逐笔恢复；
- 清空后恢复，再撤销，应重新撤销整次清空恢复操作；
- 当前图层隐藏后重新选择，历史仍属于该图层；
- 零长度图形和取消手势不进入历史；
- 现有“撤销活动笔迹不污染上一笔”行为保持不变。

## 测试与验收

### 纯 Kotlin 单元测试

- 单笔撤销和重做；
- 连续撤销/重做顺序；
- 清空作为一次整体操作恢复；
- 新元素使当前图层 redo 失效；
- 图层间历史隔离；
- 删除图层/画板、替换会话和清空会话后历史清理。

### Robolectric 结构与交互测试

- 撤销后显示 `redo-recovery-bar` 和“重做”；
- 清空后显示“恢复清空”，点击恢复全部；
- 空清空不显示恢复条；
- 新笔迹关闭旧恢复条；
- 切换图层时恢复条跟随当前图层状态；
- 恢复条在 220dp、320dp 和平板宽度下保持安全定位；
- 每次成功历史变更只触发所需的 `onSessionChanged()`。
